================================================================================
ROOT CAUSE STILL PRESENT
================================================================================

The improvements confirm that:
1. ✅ More points helps (6.6% better tracking)
2. ✅ Relative threshold is correct (prevents image-dependent issues)

But the core problem remains:
❌ Our Harris detector still selects ~15% of points that cannot be tracked

LIKELY CULPRITS (from code review):
1. **NMS window too small (3x3)**
   - Allows clustered points ~2 pixels apart
   - OpenCV uses 3-pixel Euclidean distance minimum
   - Clustered points have similar appearance → tracking fails

2. **Small structure tensor window (3x3)**
   - Makes Harris response noisy
   - Selected corners may not be stable features

3. **No sub-pixel refinement**
   - Integer coordinates only
   - Up to 0.5px positioning error

```python
def get_harris_points_with_min_distance(harris_response, threshold=0.01, 
                                        max_corners=100, min_distance=3):
    # After NMS and thresholding
    coords = ... # get candidate points
    values = ... # get their response values
    
    # Sort by response (descending)
    sorted_idx = np.argsort(values)[::-1]
    
    # Greedily select points with minimum distance
    selected = []
    for idx in sorted_idx:
        point = coords[idx]
        # Check distance to all already selected points
        if all(np.linalg.norm(point - sel) >= min_distance for sel in selected):
            selected.append(point)
            if len(selected) >= max_corners:
                break
    
    return np.array(selected)
```
